## 一、设计语言

### 1.1 视觉规范

| 属性 | 规范 |
|---|---|
| **主色** | `#B8A3E0` 薰衣草紫 |
| **深色强调** | `#6B5B8E`（按钮、标题） |
| **页面底色** | `#F5F1FA`（lavender-100） |
| **卡片底色** | `#FFFFFF` |
| **文字主色** | `#4A3D6B`（lavender-900） |
| **文字次色** | `#4F4C55`（neutral-700） |
| **文字辅助** | `#8E8A96`（neutral-500） |
| **价格色** | `#B23A48`（price-red） |
| **成功色** | `#5C8D76`（低饱和墨绿） |
| **警示色** | `#B88B4A`（库存紧张） |
| **圆角** | **全部 0px**（直角，品牌核心主张） |
| **安全边距** | 左右 `20px` |
| **间距模数** | `4px`（常用 4/8/12/16/20/24/32/48/64） |
| **阴影** | sm `0 1px 2px rgba(107,91,142,0.04)` / md `0 4px 16px rgba(107,91,142,0.06)` / lg `0 12px 40px rgba(107,91,142,0.08)` |
| **边框** | `1px solid rgba(107,91,142,0.12)` |
| **动效** | 300ms `cubic-bezier(0.2, 0.8, 0.2, 1)`，页面淡入+8px位移 |
| **hover/press** | `opacity: 0.7`，`scale(0.98)`，不变颜色 |
| **disabled** | `opacity: 0.3` |
| **毛玻璃** | 仅顶部导航（scroll后）+ 底部TabBar；`blur(20px) saturate(180%)`，`background: rgba(255,255,255,0.5)` |

### 1.2 文案规范

- 英文品牌名全小写 `intimoi`
- 中文名`双相`仅用于 logo 和页脚
- 不用 emoji
- 感叹号仅在支付失败等极少见场景
- 货币符号半角 `¥1,280`
- 标题 4–8 字，不加标点
- 不使用"您""亲"等称谓，直接表达
- 不用"抢购""爆款"等煽情词汇

### 模块 1：发现 / 首页

#### 页面说明

承载品牌调性展示与商品发现，是用户的第一印象页。

#### 页面布局（从上到下）

1. **顶部导航栏**（毛玻璃）
   - 滚动后毛玻璃生效
   - 中央显示 `intimoi` 品牌文字（font-brand，字重300，字距加宽）
   - 背景：`rgba(255,255,255,0.5)` + blur

2. **搜索栏**
   - 单行输入框，`border-radius: 0`
   - 提示文字：「搜索商品」
   - 左侧搜索图标（Lucide，`search`，24×24，1.5px描边）
   - 聚焦时下边框变 `#6B5B8E`

3. **Banner 轮播**
   - 横向自动轮播，3–5张
   - 宽高比 `3:1`，直角裁切
   - 指示器：深紫小圆点（唯一例外的圆形元素），距底部 `8px` 居中
   - 手动滑动优先于自动轮播

4. **编辑精选**
   - 区块标题：「编辑精选」
   - 布局：左1右2（左侧大图 `3:4`，右侧两张小图 `3:4`）
   - 图片：冷调高级灰，杂志风
   - 商品名 + 价格，文字不压在图片上

5. **商品列表**
   - 每行2列，瀑布流
   - 商品卡片：图片 `3:4` 直角，信息区 `16px` 间距
   - 显示：商品名、价格（红）、原价（删除线+辅助色）

#### 数据来源

- Banner：CMS 管理平台（小程序侧调用图片 URL）
- 商品数据：调用 WDT 商品接口（或自建商品 API）

#### 验收标准

- [ ] 搜索框可输入并触发搜索（展示搜索结果页）
- [ ] Banner 至少3张图，支持手动滑动

## 四、API 接口设计（基于 WDT SDK）

### 4.1 订单推送 `trade_push.php`

**用途**：用户提交订单后，小程序调用此接口将订单推送至 WDT 旺店通。

**请求参数**（小程序 → 后端 → WDT）：

| 参数 | 说明 | 示例 |
|---|---|---|
| `shop_id` | 店铺编号 | `23` |
| `trade_list`（JSON数组） | 订单列表，每条包含： | — |
| `├ tid` | 外部订单号（小程序生成） | `INTIMOI20260425001` |
| `├ trade_status` | 订单状态（20=已付款待发货） | `20` |
| `├ pay_status` | 支付状态（1=已支付） | `1` |
| `├ delivery_term` | 发货条件（2=款到发货） | `2` |
| `├ trade_time` | 下单时间 | `2026-04-25 10:00:00` |
| `├ buyer_nick` | 买家昵称 | `intimoi_user` |
| `├ receiver_mobile` | 收货人手机 | `176xxxx1203` |
| `├ receiver_name` | 收货人姓名 | `张三` |
| `├ receiver_province/city/district/address` | 收货地址 | — |
| `├ logistics_type` | 物流方式（4=快递） | `4` |
| `├ post_amount` | 运费 | `0` |
| `├ paid` | 已支付金额 | `1280` |
| `└ order_list`（JSON数组） | 商品明细 | — |
| ` ├ oid` | 子订单号 | `INTIMOI20260425001-1` |
| ` ├ goods_id` | 商品ID | `18344` |
| ` ├ spec_id` | 规格ID | `18656` |
| ` ├ goods_no` | 商品编号 | `GH001` |
| ` ├ goods_name` | 商品名 | `精华液 30ml` |
| ` ├ spec_no` | 规格编号 | `GH001-BLK` |
| ` ├ spec_name` | 规格名 | `黑色` |
| ` ├ price` | 单价 | `1280` |
| ` ├ num` | 数量 | `1` |
| ` ├ discount` | 折扣 | `0` |
| ` └ refund_status` | 退款状态（0=无退款） | `0` |

**响应**：WDT 返回 JSON，含 `code`（0=成功）和 `message`。

### 4.2 订单查询 `trade_query.php`

**用途**：查询用户订单列表和详情。

**请求参数**：

| 参数 | 说明 | 示例 |
|---|---|---|
| `start_time` | 查询开始时间 | `2026-04-01 00:00:00` |
| `end_time` | 查询结束时间 | `2026-04-25 23:59:59` |
| `page_no` | 页码（从0开始） | `0` |
| `page_size` | 每页条数 | `20` |

**响应**：WDT 返回订单列表，含订单状态、物流信息、子订单明细。

**小程序侧需处理的订单状态**：

| trade_status | pay_status | 含义 | 小程序显示 |
|---|---|---|---|
| 10 | 0 | 未付款 | 待付款 |
| 20 | 1 | 已付款 | 待发货 |
| 30 | 1 | 已发货 | 已发货 |
| 40 | 1 | 已完成 | 已完成 |
| — | — | 退款中 | 售后中 |

### 4.3 称重回传 `vip_stockout_sales_weight_push.php`

**用途**：WDT 仓库发货称重后，回传物流重量给 WDT。

**请求参数**：

| 参数 | 说明 | 示例 |
|---|---|---|
| `logistics_no` | 运单号 | `JT12121212122` |
| `weight` | 重量（kg） | `0.5` |
| `is_setting` | 是否设置为标准重量（0=普通） | `0` |

> 小程序侧通常不直接调用此接口（由 WDT 仓库系统对接），但订单详情页如需展示"称重信息"，需了解此接口存在。

### 5.1 环境切换方案

小程序需同时维护**测试环境**和**生产环境**，通过 Taro 编译标签区分。

#### 目录结构

```
miniprogram/
├── config/
│   ├── index.ts          ← 通用配置（跨环境共享）
│   ├── dev.ts            ← 开发/测试环境配置
│   ├── prod.ts           ← 生产环境配置
│   └── test.ts           ← 预发布/验收环境配置
└── src/
    ├── constants/
    │   └── env.ts         ← 环境变量统一导出
```

#### `.env` 文件（各环境独立）

```bash
# .env.dev（开发/测试）
TARO_APP_API_BASE=https://api-test.intimoi.com
TARO_APP_WDT_BASE=https://openapitest.huice.com/openapi/

# .env.prod（生产）
TARO_APP_API_BASE=https://api.intimoi.com
TARO_APP_WDT_BASE=https://openapi.huice.com/openapi/
```

#### Taro 编译标签切换

在 `package.json` 中配置：

```json
{
  "scripts": {
    "dev:weapp": "taro build --type weapp --watch",
    "dev:weapp:test": "TARO_ENV=test taro build --type weapp --watch",
    "build:weapp": "TARO_ENV=prod taro build --type weapp"
  }
}
```

#### `src/constants/env.ts` 统一导出

```typescript
// 根据编译时注入的 TARO_APP_* 变量自动读取
export const API_BASE = process.env.TARO_APP_API_BASE
export const WDT_BASE = process.env.TARO_APP_WDT_BASE

// 环境标识（用于日志/调试）
export const ENV = process.env.TARO_APP_ENV ?? 'dev'
```

#### 环境说明

| 环境 | 触发方式 | API 指向 | 使用场景 |
|---|---|---|---|
| dev | `npm run dev:weapp` | 测试环境 API | 本地开发 |
| test | `TARO_ENV=test` | 预发布 API | 验收测试 |
| prod | `TARO_ENV=prod` | 生产环境 API | 正式发布 |

#### 验收标准

- [ ] `dev` / `test` / `prod` 三套环境编译结果不同
- [ ] `.env` 文件不提交到仓库（加入 `.gitignore`）
- [ ] 切换环境后重新编译，无需改代码
- [ ] WDT 接口 base URL 随环境切换正确变化
